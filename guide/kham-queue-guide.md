# 寬宏接續購票

此功能位於 `0911-kham` 分支。不需要重建設定檔；原本只有一筆購票設定時，行為維持單場次購票。

## 使用方式

1. 初次安裝可執行根目錄的 `點我初始化0911.bat`：它會安裝獨立 Python 3.10.11、下載 `0911-kham` 分支、安裝 `requirement.txt`，成功後自動執行 `src\settings.py`，不需要 conda。已有 Python 環境時，在專案根目錄執行 `python src/settings.py` 即可；本專案開發測試使用 conda `ticketH`。
2. 網址填同一演唱會的寬宏售票主頁。原有票數、日期、區域欄位代表第一筆；啟用日期及區域自動選擇。
3. 在「寬宏接續購票」按「下一張票」，填下一個日期的票數、日期關鍵字與區域關鍵字。可新增第三筆及更多不同日期。
4. 使用「↑ 上移／↓ 下移」交換整筆資料，包含與第一筆交換。刪除後續所有票單即回到單場次模式。
5. 排除關鍵字、選擇順序及刷新間隔共用既有設定。日期請盡量填完整，例如 `2026/10/03`；多筆不接受空日期或完全相同的日期關鍵字。
6. 儲存並啟動。購票過程需要有效登入；若登入失效，完成登入後會繼續。OCR 未啟用或無法使用時，輸入四碼驗證碼後會繼續提交。

後續票單的區域關鍵字每行是一個優先序。同一行 `A區;B區` 表示任一符合，`A區 4680` 表示兩個詞都要符合。留空代表不限區域；若只接受指定區域，請關閉區域自動 fallback。

購票開始後會固定本次票單與順序，以免儲存設定時意外從第一筆重買。修改票單內容或順序需要重新啟動機器人；共用排除關鍵字、刷新間隔可透過儲存即時更新。完成後停在購物車，由使用者結帳。

## 已修正的流程

| 步驟 | 本次處理 |
| --- | --- |
| 主頁 → 場次頁 | 點擊 `GO_BUY`／我要購票，處理尚未開賣提示與載入失敗重試。 |
| 場次選擇 | 按日期及排除關鍵字選擇；找不到或未開賣按設定間隔重刷。接續票單排除已入車場次，不使用其他日期 fallback。 |
| 票區選擇 | 支援實際 HTML 的 `status_tr filter-ready` class；讀完整剩餘張數；一次讀取票區後按優先序比對，只點擊一個目標。 |
| 票別／票數／驗證碼 | 偵測電腦選位狀態、選擇非排除票別，核對實際數量後提交。保留手動選位頁的支援。驗證碼欄位實際填好才可送出。 |
| 成功視窗 | 僅辨識可見的成功提示，點擊視窗內 OK。加入失敗、驗證碼錯誤及尚未開賣不算成功。 |
| 下一筆 | 第一筆成功後立即返回同一演唱會場次頁，使用下一筆票數、日期與區域；每筆只完成一次。 |
| 最終購物車 | 逐一核對已完成場次與張數，全部在購物車才停止。尚未完成付款。 |

## 額外處理

- 送出後等待網站回應，避免反覆提交。超過等待時間會先查購物車；已入車就繼續，未入車才依設定間隔重新選區。
- 前一筆逾時消失會補買缺少的場次；只剩部分張數時只補差額，已足額的其他場次保留。
- 導航暫時失敗會保留目的頁和購票進度，不會因停在購物車就誤認全部完成。
- 網站明確提示會員／購票數量上限時，會停止接續並保留購物車，顯示原因。此狀況不會宣告全部成功。
- 完成或受限停止僅影響該瀏覽器的寬宏流程，不會建立所有機器人共用的暫停檔。

## 驗證方式與範圍

本次在 `ticketH` 執行完整測試，**61 項全部通過**：18 項瀏覽器／HTML 測試、19 項購票控制與設定相容測試、23 項日期／票區測試，以及 1 項包含多項操作的設定 UI 測試。Python 語法及 Git diff 空白檢查通過；測試前後實際 `src/settings.json` 的 SHA-256 相同。

在專案根目錄執行：

```powershell
conda activate ticketH
python -m unittest discover -s tests -p "test_kham*.py" -v
```

使用初始化 BAT 安裝的獨立 Python 時，不需執行 `conda activate`。GitHub 分支內的 `tests/fixtures/kham` 提供精簡、去識別化的 HTML 測試資料，不依賴私人 `specs` 目錄。

測試包含狀態機、保存的 HTML、實際 Chrome 中的電腦選位模擬頁，以及實際設定頁的新增／排序／儲存／preset 操作。完整流程測試使用真正的寬宏控制器、日期與區域選擇函式、票數控制和視窗處理；僅把網站導航與伺服器回應替換成離線模擬。

完整兩日測試驗證第一日 2 張紅區、第二日 1 張藍區，最後購物車有兩筆、合計 3 張；停止後再次執行迴圈不會導航或提交。另一條完整測試故意丟失第一筆成功視窗，驗證先查購物車後仍只提交兩次。

瀏覽器測試使用獨立暫存 profile。購票頁阻擋外部網路；設定頁只連本地記憶體 API，不改寫實際 `settings.json` 或 preset，也不會向寬宏送出訂單。

`specs/寬宏售票/4-seat select.html` 是手動選位頁，未提供開賣當天的電腦選位 HTML。因此目前通過的是保存頁面與電腦選位模擬的完整驗證，尚未在 EUNHYUK 真實開賣頁完成入車。現場是否出現不同 DOM、會員限購或購物車限制，仍以網站實際回應為準。範例成功提示要求 10 分鐘內結帳，接續購票不會延長網站的保留期限。

## 設定資料格式

UI 會自行處理，不需要手動編輯。新增兩筆以上時，`kham.ticket_queue` 保存完整順序；原有頂層設定同步第一筆。空清單或舊檔缺少 `kham` 時使用原本單筆設定。

```json
{
  "kham": {
    "ticket_queue": [
      {"ticket_number": 2, "date_keyword": "\"2026/10/03\"", "area_keyword": "\"紅區\""},
      {"ticket_number": 1, "date_keyword": "\"2026/10/04\"", "area_keyword": "\"藍區\""}
    ]
  }
}
```

上例日期與區域只用來說明資料格式，不代表 EUNHYUK 的實際場次。
